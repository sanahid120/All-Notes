SEO Audit & Optimization

A complete, beginner-friendly guide to understanding SEO and performing a professional website audit from keyword research through technical fixes, structured data, performance, off-page SEO, measurement, and reporting.

How to Use This Note

Learn the concepts first, then perform the audit in the same order every time. An SEO audit should not be a random list of errors. It should answer: Can search engines discover the site? Can they understand it? Is the content useful? Is the site technically healthy? Does it earn relevant visibility and traffic?

1. What Is SEO?

SEO (Search Engine Optimization) is the process of improving a website's content, structure, technical accessibility, reputation, and user experience so that search engines can discover, understand, index, and potentially show its pages for relevant searches.

On-Page SEO

Optimizing content and page elements such as titles, headings, copy, images, internal links, URLs, and metadata.

Technical SEO

Making crawling, rendering, indexing, performance, security, mobile usability, canonicalization, and site architecture work correctly.

Off-Page SEO

Building legitimate authority and visibility through relevant mentions, links, digital PR, partnerships, and useful content distribution.

Local SEO

Optimizing visibility for location-based searches using accurate business information, local content, reviews, and relevant local signals.

Important: SEO is not simply “put keywords everywhere.” Search engines need clear signals, but the primary goal is to create useful pages for people and make those pages technically accessible.

2. How Google Search Works

Think of search as a pipeline:

1. Crawling

Google discovers URLs through links, sitemaps, and other discovery mechanisms and requests resources from the site.

2. Rendering

For pages that need it, Google processes resources and JavaScript so it can understand the rendered page.

3. Indexing

Google analyzes the content and decides whether and how a page should be stored in its index.

4. Serving

For a search query, Google selects and presents relevant results and search features.

Audit principle: A page cannot rank from content quality alone if search engines cannot reliably discover, access, render, or index the important content.

3. Keyword Research — Step by Step

Keyword research identifies the language people use when searching for a product, service, problem, brand, or topic. Do not select keywords only because their search volume is high. Relevance, intent, competition, business value, and the ability to satisfy the query matter.

3.2 Brainstorm Keywords

  1. Write down the products/services offered.
  2. List customer problems and questions.
  3. List locations served.
  4. List synonyms and alternative terminology.
  5. List competitors and their categories/services.
  6. Turn each seed topic into specific search phrases.

3.3 Expand and Validate

Useful sources include:

  • Google Search suggestions and related searches.
  • Google Ads Keyword Planner.
  • Google Trends for seasonality and changing interest.
  • Google Search Console queries after the site has search data.
  • Ubersuggest for keyword ideas and estimated search metrics.
  • Semrush or Ahrefs for broader keyword and competitor research.

3.4 Build a Keyword Map

Map one primary search intent/topic to the page that should satisfy it.

URLPrimary topicIntentSecondary termsContent action
/services/web-design/web design servicesCommercialresponsive web design, website design agencyImprove service page
/blog/how-to-choose-hosting/how to choose web hostingInformationalhosting checklist, hosting guideCreate/expand article
Avoid keyword stuffing. Repeating the same keyword unnaturally can make content worse for users. Write naturally and cover the topic comprehensively.

4. On-Page SEO

4.1 Page Title

The <title> helps communicate the page's topic and is commonly used as the title link in search results.

<title>Flutter App Development Services | Company Name</title>

Best practice: make it unique, descriptive, concise, and relevant to the actual page. Do not obsess over an arbitrary character count; search displays are based on available space and can vary.

4.2 Meta Description

<meta name="description"
content="Build fast, responsive Flutter applications with API integration,
Firebase, and modern mobile UX. Explore our development services.">

Meta descriptions can help communicate what a page is about and influence search-result snippets, but Google may generate a different snippet. There is no reliable universal “580–980 pixel” rule that guarantees a particular snippet length. Write a useful, page-specific description and avoid keyword stuffing.

4.3 Headings

  • H1: the main topic/title of the page.
  • H2: major sections.
  • H3: subsections under an H2.
<h1>Flutter App Development Services</h1>
  <h2>Our Flutter Services</h2>
    <h3>Android & iOS Development</h3>
    <h3>API Integration</h3>
  <h2>Why Choose Us?</h2>

Headings are primarily a content-structure and accessibility tool. Do not use heading tags merely to make text visually large.

4.4 URL Structure

Prefer readable, stable URLs:

Good:  https://example.com/services/flutter-development/
Poor:  https://example.com/page?id=9382&cat=4&sort=desc

Use logical words, avoid unnecessary parameters, and keep URLs consistent.

4.5 Image SEO

<img src="/images/flutter-dashboard.webp"
     alt="Flutter e-commerce dashboard showing product sales">
  • Use descriptive alt text when the image conveys information.
  • Use alt="" for purely decorative images when appropriate.
  • Use meaningful filenames where practical.
  • Compress images and use modern formats such as WebP or AVIF when supported.
  • Do not stuff keywords into alt text.
  • Use responsive image techniques such as srcset when useful.

4.6 Internal Linking

Internal links help users navigate and help search engines discover related pages. Use descriptive anchor text rather than repeatedly using “click here.” 

<a href="/services/flutter-development/">
  Flutter app development services
</a>

4.7 Canonical URL

<link rel="canonical" href="https://example.com/services/flutter-development/">

Canonicalization is used when multiple URLs contain duplicate or very similar content. A canonical is a strong signal, not an absolute command to Google. Redirects are generally a stronger canonicalization signal; sitemap inclusion is weaker.

5. Content SEO

5.1 People-First Content

Create content because it helps the intended audience, not simply because a keyword has search volume. Strong content should answer the user's need, be accurate, original where appropriate, and demonstrate relevant experience or expertise.

5.2 Originality

  • Do not copy competitors' text.
  • Do not publish lightly rewritten duplicate content at scale.
  • Add original examples, screenshots, research, comparisons, experience, or analysis where appropriate.
  • Review factual accuracy and update outdated information.
  • Do not write to an arbitrary word count just because someone claims Google prefers that length.

5.3 Content Audit Questions

  • Does the page satisfy a clear search intent?
  • Is the main topic immediately understandable?
  • Does the page provide information unavailable or poorly explained elsewhere?
  • Is the information accurate and current?
  • Does the page have a clear next step for the user?
  • Are there duplicate or near-duplicate pages competing with each other?
  • Are outdated, thin, or obsolete pages candidates for improvement, consolidation, redirect, or removal?

6. Technical SEO

6.1 HTTPS

Use HTTPS for the public website. Make sure HTTP redirects to the preferred HTTPS version and that internal links consistently use HTTPS.

6.2 Sitemap.xml

A sitemap lists URLs you want search engines to know about. It is a discovery signal, not a guarantee of crawling or indexing. Include preferred canonical URLs, normally as absolute URLs. 

<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://example.com/</loc>
    <lastmod>2026-09-20</lastmod>
  </url>
  <url>
    <loc>https://example.com/services/</loc>
    <lastmod>2026-09-18</lastmod>
  </url>
</urlset>

Submit it through Google Search Console. You can also reference it in robots.txt.

6.3 robots.txt

User-agent: *
Disallow: /admin/
Disallow: /private/
Disallow: /search/

Sitemap: https://example.com/sitemap.xml
Critical distinction: robots.txt controls crawling; it is not the preferred method for removing a page from Google's index. A URL can sometimes be indexed even if its content cannot be crawled. For pages that should not appear in search, consider noindex where appropriate, authentication, or removing the content.

6.4 Indexability

Check:

  • HTTP status is normally 200 for indexable pages.
  • Important pages are not blocked by robots.txt.
  • Important pages do not have an unintended noindex.
  • Pages are accessible without login when they are intended to be public.
  • Important content is available in the rendered page.
  • Canonical signals are consistent.

6.5 Broken Links & HTTP Status Codes

StatusMeaningTypical SEO action
200Successful responseUsually fine.
301Permanent redirectUse when a page has permanently moved.
302/307Temporary redirectUse when the move is temporary.
404Not foundFix internal links; redirect only when there is a genuinely relevant replacement.
410GoneCan be appropriate when content is intentionally and permanently removed.
5xxServer errorInvestigate urgently for important URLs.

6.6 Redirects

When a page has permanently moved, use a server-side permanent redirect such as 301. Avoid long redirect chains such as A → B → C when A could point directly to C.

6.7 Large Websites: HTML Sitemap / Important Link Hub

For large sites, useful navigational pages, category hubs, breadcrumbs, and contextual internal links can help users and crawlers discover important content. An HTML sitemap can be useful when it genuinely improves navigation; it is not a substitute for a well-designed information architecture.

6.8 Mobile & JavaScript

Test the mobile version carefully. Make sure important content and links are accessible in the mobile experience. JavaScript-heavy sites should be tested with URL Inspection and rendered-page checks rather than assuming that the browser experience is identical to what a crawler can process.

7. Structured Data / Schema Markup

Structured data is machine-readable information that helps search engines understand the entities and content on a page. It can make pages eligible for certain rich search features, but adding schema does not guarantee a rich result.

7.1 JSON-LD Example

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "Example Company",
  "url": "https://example.com",
  "logo": "https://example.com/logo.png"
}
</script>

7.2 Common Schema Types

Organization

Describes an organization and its relevant details.

LocalBusiness

Useful for eligible local business information.

Product

Describes product information for eligible product pages.

Article

Describes articles, news, and other editorial content where applicable.

Recipe

For genuine recipe pages containing recipe information.

BreadcrumbList

Describes breadcrumb navigation.

VideoObject

Describes video content where the implementation meets Google's requirements.

FAQPage

Use only when the page genuinely qualifies under Google's current structured-data rules.

7.3 How to Implement Schema

  1. Identify what the page actually represents.
  2. Choose an appropriate Schema.org type.
  3. Use properties that are true and visible/appropriate for the page.
  4. Add JSON-LD to the page.
  5. Validate using Google's Rich Results Test where applicable.
  6. Use Search Console to monitor eligible rich-result reports after deployment.
  7. Fix invalid markup and keep structured data synchronized with the visible page.
Tool: Schema Markup Generator by Merkle can help generate JSON-LD, but generated markup must still be reviewed against the actual page and Google's current eligibility guidelines.

8. Website Speed & Core Web Vitals

8.1 Core Web Vitals

The current Core Web Vitals set is:

MetricMeasuresGood target
LCPLargest Contentful Paint — loading performance≤ 2.5 seconds
INPInteraction to Next Paint — responsiveness/interactivity≤ 200 ms
CLSCumulative Layout Shift — visual stability≤ 0.1

Targets are evaluated at the 75th percentile for page loads, segmented by device type.

Correction to older SEO notes: FID (First Input Delay) is no longer a Core Web Vital. INP replaced FID in the Core Web Vitals set in 2024.

8.2 Practical Speed Optimization

  • Compress oversized images.
  • Serve responsive image dimensions.
  • Use WebP or AVIF where appropriate.
  • Lazy-load below-the-fold images when appropriate.
  • Preload only truly critical resources.
  • Reduce unused CSS and JavaScript.
  • Minify CSS, JavaScript, and HTML where appropriate.
  • Defer or asynchronously load non-critical scripts.
  • Reduce third-party scripts.
  • Use browser caching with appropriate cache headers.
  • Use a CDN when it materially improves delivery.
  • Reduce server response time and database bottlenecks.
  • Prevent layout shifts by reserving dimensions for images, ads, and embeds.
  • Improve JavaScript responsiveness to reduce long main-thread tasks.

8.3 Tools

  • Google PageSpeed Insights: combines lab diagnostics with field/user data when available.
  • Chrome DevTools: investigate network requests, rendering, JavaScript, and performance.
  • GTmetrix: useful for waterfall and performance diagnostics.
  • Search Console Core Web Vitals report: monitor real-user URL groups where data is available.

9. Open Graph & Social Sharing

Open Graph tags primarily control how a URL is represented when shared on compatible social platforms. They are not a replacement for SEO title/meta tags. 

<meta property="og:title" content="Flutter App Development Services">
<meta property="og:description" content="Build modern Flutter applications...">
<meta property="og:type" content="website">
<meta property="og:url" content="https://example.com/services/flutter-development/">
<meta property="og:image" content="https://example.com/images/share-card.jpg">

10. Off-Page SEO

Off-page SEO focuses on signals and visibility outside your own website. The strongest approach is to earn relevant references because your content, business, research, tools, or services are genuinely useful.

10.1 Legitimate Link-Building Ideas

  • Create original research, statistics, tools, templates, or useful guides.
  • Publish expert resources that others naturally reference.
  • Build relationships with relevant industry publications and communities.
  • Use digital PR when you have newsworthy data or announcements.
  • Maintain accurate business profiles and relevant directories where they genuinely help users.
  • Distribute presentations, PDFs, or educational resources where the platform is relevant and allowed.

10.2 Backlink Analysis

Use tools such as Semrush, Ahrefs, Google Search Console, and other reputable crawlers to inspect:

  • Referring domains.
  • Linking pages.
  • Anchor text.
  • Lost/new links.
  • Relevant vs irrelevant links.
  • Suspicious patterns and obvious link schemes.

10.3 Toxic Backlinks & Disavow — Important Nuance

Do not assume every low-quality or strange backlink needs to be disavowed. Google can generally ignore many unnatural links algorithmically. The disavow tool is an advanced feature intended for situations such as a substantial number of artificial/spammy links that have caused or are likely to cause a manual action, especially when those links cannot be removed.

Do not mass-disavow normal links simply because a third-party tool assigns them a “toxic” score. Investigate the actual link pattern and Google's guidance before acting.

12. Complete Professional Website SEO Audit — Step by Step

Use this workflow for a new client or your own website.

1

Collect Business Information

Understand the business, products/services, locations, target customers, competitors, conversion goals, unique selling points, and current marketing channels.

2

Set Up Measurement

Verify Google Search Console ownership, confirm the correct property, connect GA4 where appropriate, and record the starting metrics.

3

Crawl the Website

Use an SEO crawler to collect URLs, status codes, titles, meta descriptions, headings, canonicals, directives, internal links, images, and other technical information.

4

Check Indexing

Review Search Console's Page Indexing report and inspect representative important URLs. Investigate excluded, blocked, duplicate, redirected, or error URLs.

5

Check robots.txt

Confirm that important resources/pages are crawlable and that intentionally restricted areas are correctly blocked.

6

Check Sitemap

Confirm the sitemap exists, is valid, contains preferred URLs, uses absolute URLs, and is submitted in Search Console.

7

Audit URL Structure & Canonicals

Look for duplicate URL variants, parameters, inconsistent trailing slashes, HTTP/HTTPS issues, www/non-www inconsistencies, incorrect canonicals, and redirect chains.

8

Audit On-Page SEO

Review titles, descriptions, H1s/H2s, content quality, URLs, image alt text, internal links, breadcrumbs, and search intent alignment.

9

Perform Keyword & Content Gap Analysis

Map existing pages to target topics. Find important queries that competitors satisfy but the site does not, then prioritize pages to improve or create.

10

Audit Structured Data

Check whether relevant schema is implemented accurately. Validate it and make sure it matches visible content.

11

Audit Performance

Check LCP, INP, CLS, server response time, image weight, JavaScript, CSS, third-party scripts, caching, mobile performance, and real-user data where available.

12

Audit Internal Linking

Find orphan pages, important pages with weak internal link support, broken internal links, excessive links, and opportunities to connect related content.

13

Audit Backlinks

Review referring domains, relevance, anchor text, lost links, suspicious patterns, and important links pointing to broken/redirected pages.

14

Check Local SEO if Applicable

Verify business name, address, phone, service area, business profile information, location pages, reviews, and local structured data where relevant.

15

Prioritize Fixes

Do not present 200 errors with equal importance. Prioritize by impact, confidence, effort, business value, and dependencies.

16

Implement & Validate

Fix the highest-impact issues, test the changes, crawl again, inspect important URLs, validate schema, and monitor Search Console.

17

Report & Repeat

Compare before/after data and maintain a recurring SEO monitoring cycle. SEO is an ongoing process, not a one-time checkbox.

14. Professional SEO Audit Report Format

A good report should be understandable to both developers and business owners.

Recommended Report Structure

  1. Executive summary — major findings and business impact.
  2. Website overview — pages, platform, market, audience, goals.
  3. Technical SEO — crawlability, indexability, sitemap, robots, canonicals, status codes.
  4. On-page SEO — titles, descriptions, headings, URLs, images, internal links.
  5. Content — quality, intent, duplication, gaps, opportunities.
  6. Performance — Core Web Vitals and speed findings.
  7. Structured data — current markup, errors, opportunities.
  8. Off-page — backlinks and authority observations.
  9. Analytics/Search Console — visibility, traffic, CTR, queries, landing pages.
  10. Prioritized action plan — what to fix first and who should do it.
  11. Measurement plan — KPIs and review frequency.

16. A Practical 30-Day SEO Learning & Execution Plan

Days 1–5: Foundations

Learn crawling, indexing, ranking, search intent, keywords, URLs, titles, headings, descriptions, canonicalization, robots.txt, and sitemaps.

Days 6–10: On-Page

Practice keyword mapping, page optimization, internal linking, image SEO, content audits, and competitor/content-gap research.

Days 11–15: Technical

Practice crawling a site, reading HTTP status codes, fixing redirects, checking indexability, testing mobile pages, and understanding JavaScript SEO.

Days 16–20: Performance & Schema

Practice PageSpeed Insights, DevTools, Core Web Vitals, image optimization, JSON-LD, Rich Results Test, and Search Console enhancement reports.

Days 21–25: Off-Page

Learn backlink analysis, referring domains, link relevance, digital PR, link schemes, and the appropriate use of Google's disavow tool.

Days 26–30: Full Audit

Choose a real website you are authorized to audit. Produce a complete report, prioritize issues, implement fixes where possible, recrawl, and document results.

18. One-Page SEO Audit Workflow

Business → Keywords → Crawl → Indexing → Technical → On-Page → Content → Internal Links → Schema → Speed → Backlinks → Analytics/Search Console → Fix → Recrawl → Report → Monitor.

Golden rule: Do not optimize for a checklist score. Optimize the website so that search engines can access and understand genuinely useful content, while users can quickly accomplish what they came to the site to do.
