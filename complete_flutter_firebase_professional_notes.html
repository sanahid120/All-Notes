1. Firebase and FlutterFire Overview

Firebase is a backend platform for authentication, databases, storage, analytics, crash reporting, notifications, remote configuration, functions, app integrity and local emulation. FlutterFire is the official set of Flutter plugins used to access Firebase products.

Authentication
Email, phone, Google, Apple, anonymous users, provider linking and session streams.
Cloud Firestore
Document database with realtime listeners, offline cache, compound queries, transactions and batches.
Realtime Database
Realtime JSON tree suited to chat, presence and rapidly changing shared state.
Cloud Storage
User-generated images, documents, audio and videos.

Enable Email/Password under Firebase Console → Authentication → Sign-in method.

  required String password,

    password: password,
  );

Future<UserCredential> signIn({
  required String email,
  required String password,
}) {
  return FirebaseAuth.instance.signInWithEmailAndPassword(
    email: email.trim(),
    password: password,
  );
}

Future<void> signOut() =>
    FirebaseAuth.instance.signOut();

Error mapping

String authMessage(FirebaseAuthException e) {
  return switch (e.code) {
    'invalid-email' => 'Invalid email address.',
    'weak-password' => 'Choose a stronger password.',
    'email-already-in-use' => 'Email is already registered.',
    'invalid-credential' => 'Email or password is incorrect.',
    'too-many-requests' => 'Too many attempts. Try later.',
    _ => e.message ?? 'Authentication failed.',
  };
}

8. Phone Authentication and SMS OTP

String? verificationId;

Future<void> sendOtp(String phoneNumber) async {
  await FirebaseAuth.instance.verifyPhoneNumber(
    phoneNumber: phoneNumber,
    timeout: const Duration(seconds: 60),
    verificationCompleted: (credential) async {
      await FirebaseAuth.instance.signInWithCredential(credential);
    },
    verificationFailed: (e) {
      throw Exception(authMessage(e));
    },
    codeSent: (id, resendToken) {
      verificationId = id;
    },
    codeAutoRetrievalTimeout: (id) {
      verificationId = id;
    },
  );
}

Future<UserCredential> verifyOtp(String code) {
  final id = verificationId;
  if (id == null) throw StateError('Request OTP first.');

  final credential = PhoneAuthProvider.credential(
    verificationId: id,
    smsCode: code.trim(),
  );
  return FirebaseAuth.instance.signInWithCredential(credential);
}

Web phone auth

final confirmation = await FirebaseAuth.instance
    .signInWithPhoneNumber(phoneNumber);
final result = await confirmation.confirm(smsCode);
SMS is not phishing-resistant. Add rate limiting, abuse monitoring, rules and App Check.

9. Complete User Profile Model

class AppUser {
  final String uid;
  final String email;
  final String displayName;
  final String? photoUrl;
  final String role;
  final DateTime createdAt;

  const AppUser({
    required this.uid,
    required this.email,
    required this.displayName,
    required this.photoUrl,
    required this.role,
    required this.createdAt,
  });

  factory AppUser.fromFirestore(
    DocumentSnapshot<Map<String, dynamic>> doc,
  ) {
    final data = doc.data()!;
    return AppUser(
      uid: doc.id,
      email: data['email'] as String? ?? '',
      displayName: data['displayName'] as String? ?? '',
      photoUrl: data['photoUrl'] as String?,
      role: data['role'] as String? ?? 'customer',
      createdAt: (data['createdAt'] as Timestamp?)?.toDate()
          ?? DateTime.now(),
    );
  }
}

Future<String> uploadFile(File file, String uid) async {
  final name = '${DateTime.now().microsecondsSinceEpoch}.jpg';
  final ref = FirebaseStorage.instance
      .ref('users/$uid/uploads/$name');

  final task = ref.putFile(
    file,
    SettableMetadata(contentType: 'image/jpeg'),
  );

  task.snapshotEvents.listen((snapshot) {
    final progress = snapshot.totalBytes == 0
        ? 0.0
        : snapshot.bytesTransferred / snapshot.totalBytes;
    debugPrint('${(progress * 100).toStringAsFixed(1)}%');
  });

  final snapshot = await task;
  return snapshot.ref.getDownloadURL();
}

Complete profile photo update

Future<String> updateProfilePhoto() async {
  final user = FirebaseAuth.instance.currentUser;
  if (user == null) throw StateError('Not signed in');

  final picked = await ImagePicker().pickImage(
    source: ImageSource.gallery,
    imageQuality: 82,
    maxWidth: 1600,
  );
  if (picked == null) throw StateError('Cancelled');

  final extension = picked.name.split('.').last.toLowerCase();
  final ref = FirebaseStorage.instance
      .ref('profile_images/${user.uid}/avatar.$extension');

  await ref.putFile(
    File(picked.path),
    SettableMetadata(
      contentType: 'image/$extension',
      customMetadata: {'ownerId': user.uid},
    ),
  );

  final url = await ref.getDownloadURL();
  await user.updatePhotoURL(url);

  await FirebaseFirestore.instance
      .collection('users')
      .doc(user.uid)
      .set({
    'photoUrl': url,
    'updatedAt': FieldValue.serverTimestamp(),
  }, SetOptions(merge: true));

  return url;
}

Multiple product images

Future<List<String>> uploadProductImages(
  String productId,
  List<XFile> files,
) async {
  final urls = <String>[];
  for (var i = 0; i < files.length; i++) {
    final file = files[i];
    final ref = FirebaseStorage.instance
        .ref('products/$productId/${i}_${file.name}');
    await ref.putFile(File(file.path));
    urls.add(await ref.getDownloadURL());
  }
  return urls;
}

20. Security Rules

Firestore

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function signedIn() { return request.auth != null; }
    function owns(uid) {
      return signedIn() && request.auth.uid == uid;
    }

    match /users/{uid} {
      allow read, update, delete: if owns(uid);
      allow create: if owns(uid)
        && request.resource.data.role == 'customer';
    }

    match /products/{id} {
      allow read: if resource.data.isActive == true;
      allow write: if signedIn()
        && request.auth.token.admin == true;
    }

    match /orders/{id} {
      allow create: if signedIn()
        && request.resource.data.userId == request.auth.uid;
      allow read: if signedIn()
        && resource.data.userId == request.auth.uid;
      allow update, delete: if false;
    }
  }
}

Realtime Database

{
  "rules": {
    "users": {
      "$uid": {
        ".read": "auth != null && auth.uid == $uid",
        ".write": "auth != null && auth.uid == $uid"
      }
    }
  }
}

Storage

rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /profile_images/{uid}/{fileName} {
      allow read: if true;
      allow write: if request.auth != null
        && request.auth.uid == uid
        && request.resource.size < 5 * 1024 * 1024
        && request.resource.contentType.matches('image/.*');
    }
  }
}
Rules are the real authorization boundary. Hiding an admin button in Flutter does not secure data.

21. Custom Claims, App Check and Trusted Backend Work

Set roles such as admin only from a trusted server using the Admin SDK. Never set them from Flutter client code.

await FirebaseAuth.instance.currentUser?.getIdToken(true);
final result = await FirebaseAuth.instance
    .currentUser
    ?.getIdTokenResult();
final isAdmin = result?.claims?['admin'] == true;

App Check helps reject unauthorized clients. It supplements—but never replaces—security rules.

  • Assign roles/custom claims on a trusted backend.
  • Create payment intents and verify webhooks on a backend.
  • Send privileged notifications from trusted code.
  • Perform cross-user administration with Admin SDK.
  • Keep service-account keys and private secrets out of Flutter.

24. Offline, Performance and Cost Control

  • Use realtime listeners only where realtime behavior matters.
  • Paginate large Firestore queries and Storage listings.
  • Listen at the narrowest Realtime Database path.
  • Add RTDB .indexOn rules for queried fields.
  • Compress and resize images before upload.
  • Store the Storage path as well as the download URL.
  • Delete replaced or orphaned files.
  • Avoid unlimited arrays and oversized Firestore documents.
  • Use server timestamps, transactions and batches for critical state.

26. Production Checklist

  • Separate development, staging and production projects.
  • Configure each platform and environment with FlutterFire CLI.
  • Add debug and release fingerprints.
  • Enable only required auth providers.
  • Require email verification where needed.
  • Deploy restrictive, tested rules.
  • Enable App Check after monitoring legitimate traffic.
  • Use transactions for inventory and money-related state.
  • Use a backend for payments and privileged actions.
  • Plan account deletion across Auth, databases and Storage.
  • Monitor quotas, billing, crash reports and performance.
